# DocuSync AI repository audit

## Canonical implementation

Use [hackathon-project/project](../hackathon-project/project) for the application. It already contains the most complete deterministic PDF pipeline, a local Flask dashboard, tests and PowerPoint repair. Its batch CLI and dashboard share extraction code. The single-document workspace extends that dashboard and uses the same intermediate representation and XML serializer. The starter remains the simpler native-text baseline.

The written competition brief has precedence over the sample according to both implementations' documentation. Those documents report that the brief calls for HTML-style elements and page wrappers with `n`. The app defaults to `brief` and validates against the local structural checks.

Its external binary and traineddata are independent of the Python requirements. [Upstream installation notes](https://github.com/tesseract-ocr/tessdoc/blob/main/Installation.md), [Mannheim build](https://digi.bib.uni-mannheim.de/tesseract/), [tessdata_fast](https://github.com/tesseract-ocr/tessdata_fast)

A Windows CPU adapter trial should confirm model routing and compare OCR quality and total runtime against the now-running Tesseract baseline. - Ollama is installed and the local model list was empty. The Qwen3 4B published Q4_K_M artifact is about 2.5 GB on disk. It is a CPU trial candidate with short inputs and a small context. Actual memory use, latency and the specific Radeon runtime still require a target-machine run. The workspace defaults to deterministic processing and can request an optional structured comparison hint from an installed local model. ## Prioritized blockers and migration

1. Obtain the organizer brief, golden XML/PDF/PPTX, screenshots and authorized Phase 1 and Phase 2 material. These are needed for format acceptance, performance, accuracy and visual fidelity verification.
2. Keep the Windows baseline reproducible with the isolated environment and Tesseract language packs. Store local inputs, outputs and review artifacts under ignored directories. Audit confidential files and tracked dependency history before sharing or submission.
3. Validate the single-upload workspace against the corpus while preserving batch behavior. Its UUID storage isolates originals and job attempts. The metadata overlay and XML generation share the reviewed IR. Use the batch engine as the deterministic reference for further changes.
4. Benchmark OCR and layout adapters with labeled examples. Preserve existing text, geometry and provenance fields across changes to the IR. Evaluate whether Pydantic validation would improve persisted IR checks before changing its serialization.
5. Extend higher-risk changes conservatively. Compare known changes to golden reports and validate each affected PPTX while preserving unrelated slides and source files. Team identity and a wider deployment require authentication and an explicit hosting decision.

Risks include changing reading order or language labels as OCR and layout adapters are introduced, breaking legacy output naming, drifting from the organizer XML schema and over-applying deck edits on paraphrased slides. Keep phase directories and old artifacts available. Use small changes with regression tests and distinct output paths.
